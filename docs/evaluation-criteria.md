# Критерії оцінювання ефективності IDS

## Критерії

| Критерій | Що оцінюється | Джерело даних |
|---|---|---|
| Факт виявлення активності | Чи зафіксувала IDS тестовий сценарій | `fast.log` |
| Відповідність сценарію | Чи відповідає спрацювання виконаному тесту | Повідомлення правила, SID |
| Повнота журналів | Наявність IP-адрес, портів, протоколів і SID | `fast.log`, за потреби `eve.json` |
| Точність спрацювань | Чи реагує правило саме на потрібний тип активності | Порівняння тесту і запису в журналі |
| Надмірні сповіщення | Чи створюються зайві або повторні повідомлення | Кількість записів у журналі |
| Виявлення вебатак | Фіксація SQL-injection і login-запитів | `fast.log` |
| Робота під навантаженням | Фіксація HTTP-трафіку під час ApacheBench | `fast.log`, результат ApacheBench |
| Використання ресурсів | Зміна CPU, RAM і RSS процесу Suricata | `ps`, `watch`, системний моніторинг |

## Результати оцінювання

| Критерій оцінювання | Результат |
|---|---|
| Виявлення ICMP-трафіку | ✅ Успішно зафіксовано (`TEST ICMP rule`) |
| Виявлення TCP-активності під час Nmap | ✅ Успішно зафіксовано (`TEST TCP scan traffic`) |
| Виявлення SQL-injection запиту | ✅ Успішно зафіксовано (`TEST SQL keyword UNION/SELECT`) |
| Виявлення багаторазових login-запитів | ✅ Успішно зафіксовано (`TEST Juice Shop login attempt`) |
| Виявлення SSH-підключення | ✅ Успішно зафіксовано (`TEST SSH connection attempt`) |
| Виявлення HTTP-навантаження | ✅ Успішно зафіксовано, трафік до Juice Shop |
| Повнота журналів | `fast.log` містив SID, повідомлення, протокол, IP-адреси та порти |
| Надмірні сповіщення | Виявлено під час TCP- та HTTP-тестів через широкі сигнатури |
| Вплив на ресурси системи | Критичного зростання CPU/RAM у межах короткого тесту не зафіксовано |
| Загальна працездатність IDS | Підтверджена в усіх 6 проведених тестових сценаріях |

## Споживання ресурсів під навантаженням

| Стан | CPU | RAM | RSS |
|---|---|---|---|
| До навантаження | 2.0% | 7.8% | 615 512 KB |
| Після навантаження (20 000 HTTP-запитів) | 3.0% | 10.2% | 799 416 KB |

**Висновок:** навантажувальний тест (20 000 запитів через ApacheBench, 0 невдалих
запитів, ~222 req/sec) не призвів до критичного зростання споживання ресурсів
процесом Suricata — приріст CPU і RAM залишався в межах кількох відсотків.
